kults.tech / deployment handoff

Put the work
where people can see it.

This guide explains how to publish the main kults.tech website on GitHub Pages and how the four sample project pages are connected to the portfolio.

What is already prepared

The main site now contains four portfolio cards with direct links to the sample pages. Each sample is stored under a predictable relative path, so the links work without a database, API, or server-side application.

index.html work/ ├── tala/index.html ├── folio-house/index.html ├── pulse/index.html └── loop-radio/index.html
Important: GitHub Pages is static hosting. The visual pages will work there immediately, but the contact form is currently a front-end brief collector. Connect it to Formspree, Netlify Forms, or a small backend before relying on it for real enquiries.

Step 1 — Build the publishable files

  1. From the project root, run pnpm build. This creates the publishable static site inside dist/public/.
  2. Use the contents of dist/public/ as the GitHub Pages repository root—not the raw client/src/ React source.
  3. Make sure the published root contains the main index.html and the work/ directory at the same level.
  4. Do not move the sample HTML files out of their folders unless you also update their image paths.

Step 2 — Create the GitHub repository

  1. Sign in to GitHub and create a new repository, for example kults-tech-site.
  2. For a personal site at username.github.io, name the repository exactly username.github.io. Otherwise, GitHub Pages will publish it at username.github.io/kults-tech-site/.
  3. Keep the repository public if you are using GitHub’s free Pages hosting.

Step 3 — Upload and publish

git init
git add .
git commit -m "Launch kults.tech studio site"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/YOUR-REPO.git
git push -u origin main
  1. Open the repository’s Settings → Pages.
  2. Under Build and deployment, choose Deploy from a branch.
  3. Select main and the /root folder, then save.
  4. Wait for GitHub to finish the Pages deployment. The site URL will appear in the Pages panel.

Step 4 — Confirm the sample links

From the main site, test each portfolio card:

  • work/tala/ → TALA — Architecture + Landscape
  • work/folio-house/ → Folio House — Independent Publishing
  • work/pulse/ → PULSE — Contemporary Dance
  • work/loop-radio/ → LOOP — Neighborhood Radio

Open each page on desktop and mobile. Confirm that the page loads its local images and that refreshing the sample URL still works.

Step 5 — Connect the domain

  1. In GitHub Pages, add your custom domain, such as kults.tech.
  2. At the domain registrar, add the DNS records GitHub provides. Usually this means apex A records pointing to GitHub Pages and a www CNAME pointing to your GitHub Pages hostname.
  3. Return to GitHub Pages, enable HTTPS, and wait for the certificate to become active.
  4. Test both https://kults.tech and https://www.kults.tech, then choose one as the canonical version.

Step 6 — Keep the site maintainable

When a new sample project is ready, create a new folder under work/, place its standalone index.html and image assets inside, add one project object to the main site, and redeploy. Keep paths relative—use work/new-project/ rather than a machine-specific file path.
